Teoría y Glosario

Fundamentos de arquitectura x86 y definiciones clave.

1. Modo Real — El modelo de memoria del 8086 ▾

El procesador Intel 8086 implementó un modelo de memoria segmentada con un espacio de direccionamiento de 20 bits (1 MiB). Dado que los registros internos son de 16 bits, el cálculo de la dirección física requiere la siguiente operación:

Dirección física = Segmento × 10h + Offset

El segmento se desplaza cuatro posiciones a la izquierda (multiplicación por 16) para obtener la dirección base del segmento. A continuación se suma el desplazamiento (offset) de 16 bits.

Desbordamiento de 20 bits: Si la dirección aritmética supera los 20 bits (1048575 = FFFFFh), el procesador 8086 original aplica un wrap: los bits superiores se descartan y solo se conservan los 20 inferiores. Con la línea A20 habilitada en sistemas modernos, el bit 20 también se transmite.

2. Modo Protegido — Selectores y descriptores ▾

En el modo protegido de 32 bits, los registros de segmento contienen selectores de 16 bits, no direcciones base directas. El selector identifica una entrada de la GDT o LDT:

  • Bits 15–3: Índice de la entrada en la tabla (0–8191).
  • Bit 2 (TI): 0 = GDT, 1 = LDT.
  • Bits 1–0 (RPL): Nivel de privilegio solicitado (0 = mayor, 3 = menor).

El descriptor de 8 bytes contiene la base (32 bits), el límite (20 bits), los atributos y los indicadores de control. La dirección lineal se calcula como:

Dirección lineal = Base del segmento + Offset

La dirección física requiere paginación para ser determinada. Si la paginación está deshabilitada, la dirección lineal coincide con la física.

4. Tipos de segmentos — Interpretación del campo Tipo ▾

Cuando S=1 (código/datos), los 4 bits del campo Tipo se interpretan así:

Segmentos de Datos (bit 3 = 0):

  • Bit 2: Expansión descendente (E) — 0 = hacia arriba, 1 = hacia abajo
  • Bit 1: Escritura (W) — 0 = solo lectura, 1 = lectura/escritura
  • Bit 0: Accedido (A)

Segmentos de Código (bit 3 = 1):

  • Bit 2: Conformidad (C) — 0 = no conforme, 1 = conforme
  • Bit 1: Lectura (R) — 0 = solo ejecución, 1 = ejecución/lectura
  • Bit 0: Accedido (A)

Cuando S=0 (descriptor de sistema), el campo Tipo identifica puertas de llamada, puertas de interrupción, descriptores TSS, descriptores LDT, etc.

Glosario de términos
Segmento
Región de memoria con una base, un límite y atributos de acceso. En modo real, la base se calcula como Segmento × 16.
Offset
Desplazamiento dentro de un segmento, medido en bytes desde la base del segmento.
Dirección física
Dirección real en el bus de memoria que corresponde a una celda de la RAM. En modo real coincide con la aritmética segmento:offset. En modo protegido puede requerir paginación.
Dirección lineal
Resultado de sumar la base del segmento al offset en modo protegido. Si la paginación está deshabilitada, coincide con la dirección física.
Selector
Valor de 16 bits almacenado en un registro de segmento (CS, DS, SS, etc.) que identifica una entrada de la GDT o LDT.
Descriptor
Estructura de 8 bytes en la GDT o LDT que describe las características de un segmento: base, límite, tipo y atributos.
GDT
Global Descriptor Table. Tabla de descriptores accesible por todo el sistema. El registro GDTR apunta a ella.
LDT
Local Descriptor Table. Tabla de descriptores específica de un proceso o tarea. El registro LDTR la referencia.
DPL
Descriptor Privilege Level. Nivel de privilegio del segmento definido en el descriptor (0 = más privilegiado, 3 = menos).
RPL
Requested Privilege Level. Bits 1–0 del selector. Indica el nivel de privilegio solicitado por quien accede al segmento.
TI
Table Indicator. Bit 2 del selector. 0 = usar GDT, 1 = usar LDT.
Límite
Tamaño máximo del segmento menos uno. Con G=0 se mide en bytes (20 bits, máx. ~1 MiB). Con G=1 se mide en páginas de 4 KiB (máx. 4 GiB).
Base
Dirección lineal del primer byte del segmento. De 32 bits en modo protegido de 32 bits.
Granularidad (G)
Bit 55 del descriptor. G=0: límite en bytes. G=1: límite en páginas de 4 KiB (límite efectivo = límite × 4096 + 4095).
Paginación
Mecanismo que divide la memoria en páginas de tamaño fijo y mapea direcciones lineales a direcciones físicas mediante tablas de páginas.
Privilegio
Mecanismo de protección que controla qué código puede acceder a qué recursos. El procesador compara CPL, RPL y DPL al cargar selectores.
Presencia (P)
Bit 47 del descriptor. P=1: el segmento está cargado en memoria. P=0: genera una excepción de segmento no presente al acceder.

Aplicación educativa para estudiantes de Arquitectura de Computadores. Permite calcular, visualizar y analizar el direccionamiento x86 en Modo Real y Modo Protegido.

Guía de exposición (~5 minutos)

1. Modo Real (1 min 30 s)

Navegar a Modo Real. Pulsar el ejemplo 1000h:0020h → mostrar resultado 10020h. Pulsar Paso a paso y avanzar por cada operación (multiplicación, suma, dirección final). Cambiar al modelo A20 y mostrar la diferencia al usar FFFFh:FFFFh.

2. Modo Protegido (2 min)

Ir a Modo Protegido → Modo Tabla. Pulsar Cargar GDT ejemplo. Usar selector 0008h con registro DS y offset 00001000h. Mostrar la resolución del selector (índice=1, TI=0 → GDT), la decodificación del descriptor y la dirección lineal resultante. Intentar usar el mismo selector con CS para mostrar el rechazo de tipo.

3. Reversing (1 min 30 s)

Ir a Reversing. Pulsar Cargar ejemplo y luego Analizar descriptor. Señalar cada campo coloreado, explicar base, límite efectivo, tipo y privilegios. Pulsar Paso a paso y recorrer los campos uno por uno.

⚠
Limitaciones conocidas
El simulador de paginación es didáctico: las tablas de páginas son de ejemplo y no reproducen una configuración real del sistema operativo.
Las comprobaciones de privilegio implementadas son las principales (CPL, RPL, DPL básico). No reproducen la totalidad de las reglas de acceso en llamadas con cambio de nivel.
El modelo de 32 bits no cubre el modo de 64 bits (IA-32e/long mode), donde la segmentación tiene un rol reducido.
No se simula TLB, caché ni ciclos de bus reales.

Recorrido guiado — ARQ LAB

Sigue este recorrido para conocer las funcionalidades principales de la aplicación.

  1. Ir a Modo Real y calcular la dirección para el ejemplo 1000h:0020h.
  2. Activar Paso a paso para ver cada operación explicada.
  3. Ir a Modo Protegido → Modo Tabla y cargar la GDT de ejemplo.
  4. Resolver el selector 0008h con DS y un offset para obtener la dirección lineal.
  5. Ir a Reversing, cargar un descriptor de ejemplo y explorar sus campos.
